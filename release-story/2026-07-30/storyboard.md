# Claude Code Agent Monitor (ccam) — storyboard outline
**Source:** release-story.md (generated 2026-07-30)
**Frame count:** 6 across 5 domains (Plans, Focus Reporting ×2, Kanban Board, Sessions, Settings)

## Frame 1 — Focus, declared and tracked
- **Screen:** A session card on the Kanban board or Sessions list for an active session, showing its plan breadcrumb line (e.g. "Item 3: Plan Tracking") under the session name, with a drift badge lit up to indicate declared focus and actual activity have diverged. Paired in the same frame: a terminal pane showing `ccam focus set 3` (or `ccam focus push "investigating a flaky test"`) being run — the CLI command that produces the card state shown. Both are reachable per the story unit's own "Where to find it": CLI commands documented under `ccam help`, and the card/breadcrumb rendering on Kanban, Sessions, `SessionDetail`'s Plan tab, and the Plan modal opened from Projects/Kanban project headers.
- **Why:** Represents the Plans domain's core value — turning "active" into "active on what, and is it still on-plan" — and, by pairing the CLI command with its on-screen effect, also gives the storyboard a frame for the CLI surface, the only surface besides the web app with user-facing story units in this release (per Solution composition). Draws from "Session focus declarations, detours, and drift auditing."
- **Caption:** "Every session now says what it's working on — and flags it the moment it wanders off the plan."

## Frame 2 — The whole portfolio, one timeline
- **Screen:** The Calendar page (sidebar → Calendar, `/focus-calendar`), showing swim lanes for several concurrent sessions across multiple projects at once, one block's hover popup open with its active/idle striping visible, and the zoom bar (4h/8h/12h/24h) shown narrowing the visible window.
- **Why:** Represents Focus Reporting's most visually rich and highest-impact new surface — a genuinely new capability (portfolio-wide view) rather than a refinement of the older per-project modal. Draws from "Focus Calendar board (cross-project)."
- **Caption:** "See what every monitored project was actually doing, side by side, on one timeline."

## Frame 3 — What happened, in plain English
- **Screen:** The Focus page (sidebar → Focus, `/focus`) with a project and time window selected, scrolled to the Summary block showing a finished AI-generated narrative ("what happened this week") with model attribution, above the itemized per-plan-item/detour/bug/feature list.
- **Why:** Represents the second, complementary Focus Reporting surface — built for a non-technical stakeholder rather than someone reading a swim-lane grid. Distinct enough from Frame 2 (narrative vs. timeline) to earn its own frame despite sharing a domain. Draws from "Focus page: plain-English activity summaries."
- **Caption:** "A plain-English summary of what actually got done — no chart-reading required."

## Frame 4 — A desk layout that follows you
- **Screen:** Kanban board, Projects view (`/kanban`), showing two named "monitor" boxes side by side, each containing several project columns dragged into it, with one box collapsed into a strip.
- **Why:** Represents Kanban Board's most illustrative new capability this release — a layout that mirrors a user's physical multi-monitor desk and now syncs live across browsers, rather than a minor UI decluttering. Draws from "Monitor groupings (draggable 'desk layout' boxes)."
- **Caption:** "Group your project columns to match your monitor setup — and it follows you to any browser."

## Frame 5 — Context pressure, made visible
- **Screen:** A session's detail page (`/sessions/:id`), scrolled to the per-turn context-size chart: a sawtooth pattern of context growth with a visible drop at a `/compact` event, and labeled gridlines at 0/25/50/75/100% of the session's max observed context showing actual token counts.
- **Why:** Represents the deepest new piece of session-level insight shipped this release — turning raw token totals into an at-a-glance signal of context pressure — which speaks to Sessions' core "see what's happening in a session" value more directly than the domain's other units. Draws from "Per-turn context-size chart."
- **Caption:** "Watch a session's context window fill up turn by turn, and see exactly when a compact reset it."

## Frame 6 — Know which build you're looking at
- **Screen:** The sidebar, expanded, showing the small card pinned above the brand block reading "Dev" or "Built" depending on the current tab, then that card being clicked to jump to the other build at the same path.
- **Why:** Represents Settings' one user-facing story unit this release — a small but concrete affordance for telling the Vite dev server apart from the production bundle when both can run on arbitrary ports. Draws from "Dev vs. production build indicator." Scoped deliberately to the web app tab: the release story's Needs review → Surface tag mismatches flags unresolved doubt about whether this indicator's whole premise (comparing localhost ports across browser tabs) means anything inside the Desktop app's address-bar-less Electron window, so this frame should not be read as also covering Desktop.
- **Caption:** "Always know at a glance whether you're looking at the dev build or the production build."

## Coverage notes
- **Domains with no frame:** none — all 5 domains (Plans, Focus Reporting, Kanban Board, Sessions, Settings) got at least one frame; Focus Reporting got two because its two new pages (Calendar vs. Focus) are genuinely distinct surfaces, not a refinement of the same screen.
- **Domains merged/consolidated:** none merged. Within-domain story units left out of the frame list (not domains dropped, just thinner or redundant units within a covered domain):
  - **Plans:** "Hierarchical plan sub-items" not selected — same Plan modal surface as Frame 1, a structural refinement rather than the domain's core value. "Stable plan-item identity across reorders" skipped outright — its own Proof point is `N/A` (invisible backend correctness fix).
  - **Focus Reporting:** "Per-project focus-time report" not selected — same time-bar concept as the Calendar (Frame 2) but single-project only, so the richer cross-project view was chosen instead. "Focus summary cache visibility (Settings)" not selected — a thinner, Settings-facing sub-feature of the Focus page's summary generation already shown in Frame 3.
  - **Kanban Board:** "Consolidated status filters" not selected — a header-decluttering fix, not a new capability. "Shareable dashboard link" not selected — a real, distinct capability, but its own Proof point (a token briefly visible then vanishing from the address bar) is a subtler, harder-to-shoot beat than Monitor groupings, and the release story's Needs review → Surface tag mismatches flags unresolved doubt about whether its URL-cleanup behavior means anything inside Desktop's window — a cleaner Kanban frame was preferred per the selection heuristic.
  - **Sessions:** "Per-session delete," "Honest 'still working' status for background activity," "Jump to a session's live terminal tab," and "Open a new terminal in a project" were all considered. The context-size chart (Frame 5) was chosen as the single most illustrative because it is the newest, most self-explanatory visualization and reflects the domain's core monitoring value most directly. Note for the human reviewer: the two terminal-integration units together represent a genuinely distinct OS-level capability (and are the subject of the most recent commits in this range) that got no frame in this pass — worth a second look if terminal integration is a priority to showcase.
  - **Settings:** only one user-facing story unit exists in this release; it was used directly.
- **Known gap inherited from the release story, not introduced here:** the release story's own Needs review → Likely-missing coverage flags that the Projects page and its backing API (created in `e97c514`) have no dedicated story unit despite being foundational to several units drawn on above (Frame 4's "Projects view," and the Kanban/Projects entry points cited by Frames 1–2's source units). No frame was invented for it here, per this task's scope — it should not be shot until a human reviewer adds a proper story unit for it.
- **Surfaces named in Solution composition with zero coverage:** `mcp/`, `vscode-extension/`, and `plugins/` had zero commits in this release and accordingly have no story units and no frames — a real absence in what shipped, not a curation choice. The Desktop wrapper automatically inherits every Web app frame above (it embeds the same `client/`+`server/` in-process per Solution composition) and so was not given its own frame, except that two of the release story's own open questions — the Shareable-link URL cleanup and the Dev/prod indicator (Frame 6) — remain unverified as to whether they function meaningfully inside Desktop's window; neither is resolved by this storyboard.
